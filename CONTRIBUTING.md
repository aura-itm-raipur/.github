# Contributing to AURA

Thank you for helping improve AURA. This document explains the contribution process for members and collaborators.

## Getting Started

1. Fork the repository.
2. Create a branch for your work.
3. Make your changes.
4. Open a pull request.

## Branch Naming

Use clear, descriptive branch names.

Recommended format:

- `feature/<short-description>`
- `fix/<short-description>`
- `docs/<short-description>`
- `chore/<short-description>`
- `refactor/<short-description>`

Examples:

- `feature/member-showcase`
- `fix/banner-alignment`
- `docs/readme-update`

## Commit Message Format

Use short, direct commit messages.

Recommended format:

- `type: short description`

Common types:

- `feat`
- `fix`
- `docs`
- `style`
- `refactor`
- `test`
- `chore`

Examples:

- `feat: add member showcase`
- `docs: update contributing guide`
- `fix: improve README footer spacing`

Keep commits focused on a single logical change whenever possible.

## Pull Request Guidelines

Before opening a pull request:

- Ensure the branch is up to date with the main branch.
- Keep the PR focused on one topic.
- Add a short summary of what changed.
- Mention any related issue or discussion.
- Include screenshots when the change affects visuals.
- Verify there are no broken links, markdown errors, or formatting issues.

A PR should be easy to review and should not mix unrelated changes.

## Code Style

When contributing code or scripts:

- Match the existing style of the repository.
- Keep changes small and readable.
- Prefer simple, maintainable solutions.
- Use consistent indentation and formatting.
- Avoid unnecessary dependencies.
- Test changes when possible before opening a PR.

## Documentation Rules

Documentation is part of the project and should be kept current.

- Update README files when behavior changes.
- Keep instructions accurate and easy to follow.
- Use clear language and avoid unnecessary jargon.
- Add examples when they improve understanding.
- Check links, paths, and image references after editing.
- Make sure markdown renders correctly on GitHub.

## Need Help?

If you are unsure how to contribute, open an issue or ask a maintainer before making large changes.
